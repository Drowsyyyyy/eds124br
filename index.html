Repeats — Code Explanation

The purpose of my program is to animate a breakdancer who says “Let’s Dance!”, moves to the right, does a full flip, returns, changes size, and says goodbye — using repeat loops to keep the code concise.

The way my code works is: a repeat loop moves the dancer right 4 times (change x by 20 with a short wait each time); another repeat turns the dancer 36° ten times to complete a flip; another repeat moves left 4 times; and a final repeat shrinks the dancer in five steps. Each loop highlights how repetition automates repeated actions.

If I were to change a repeat — for example, doubling the “move right” loop from 4 to 8 — the dancer would travel twice as far before flipping. Reducing the flip loop from 10 to 5 would result in only a half rotation instead of a full flip.

Tool: Snap (snap.berkeley.edu)  •  Concept focus: Nested repeat (inner/outer)  •  No variables, conditionals, or events beyond green flag.

Learning Objective

Students will see how an inner loop constructs one unit (a square) while the outer loop repeats and rotates that unit to produce a complex pattern. They will predict outputs when loop counts/angles change (e.g., 24 × 15° also totals 360°).

Program (Block Sequence)

  5. (optional) set pen color to any
  6. pen down

    1. repeat 4

      2. turn 90 degrees
    2. turn 10 degrees
  8. pen up

How my code uses events

Stage

  • when green flag clicked → switch backdrop to Stage, stop all sounds.
  • when [space] key pressed → broadcast [party].

Drummer

  • when green flag clicked → go to x:-200 y:-60, set size 80%.
  • when [D] key pressed → play drum sound + flash hit costume.
  • when I receive [party] → short drum-bounce loop.

Guitarist

  • when green flag clicked → go to x:200 y:-60.
  • when [G] key pressed → strum + brief tilt.
  • when I receive [party] → strum loop with costume changes.

Dancer

  • when green flag clicked → center & set rotation style.
  • when this sprite clicked → quick spin.
  • when I receive [party] → 2-second dance pattern.

Event-focused explanation: the key idea is timing. Each handler runs only when its event occurs. Keys and clicks are independent; the broadcast synchronizes many sprites at once. No variables/ifs—just events + simple looks/motion/sound.

If I change an event, how does behavior change?

  • Change broadcast [party] to broadcast [showtime] → nothing happens until listeners are updated to when I receive [showtime].
  • Move drummer’s party actions from when I receive [party] to when [D] key pressed → drummer won’t join the synchronized performance; it only reacts to D.
  • Lesson: events define when code runs and how sprites coordinate.

  2. Add the exact event blocks listed above. Keep it to events + simple motion/look/sound (no ifs or variables).
  3. Test: Press D/G any time. Click the Dancer. Press space to broadcast party and watch synchronized behavior.

Variable-Driven Polygons — Seeing Variables & Events in Snap

Tool: Snap (snap.berkeley.edu)  •  Concepts: Variables and Events  •  No conditionals or while/until loops.

Learning Objective

Students will use variables to control a drawing (number of sides and side length) and use events (green flag and key presses) to change those variables, observing immediate, predictable effects.

Variables

  • sides — how many sides the polygon has (e.g., 5).
  • length — the side length used for drawing (e.g., 100).
  • angle — computed as 360 / sides for the turn.

Event Scripts

  1. when green flag clicked → set sides to 5, set length to 100, broadcast [redraw]
  2. when up arrow key pressed → change sides by 1, broadcast [redraw]
  3. when down arrow key pressed → change sides by -1, broadcast [redraw]
  4. when L key pressed → change length by 10, broadcast [redraw]
  5. when K key pressed → change length by -10, broadcast [redraw]

Drawing Script (Triggered by Event)

  1. when I receive [redraw]
  2. clear, go to x: 0 y: 0, set pen size to 2, set angle to (360 / sides), pen down
  3. repeat sides times:
    1. move (length)
    2. turn (angle)
  4. pen up

when green flag clicked
set [sides v] to (5)
set [length v] to (100)
broadcast [redraw v]

when [up arrow v] key pressed
change [sides v] by (1)
broadcast [redraw v]

when [down arrow v] key pressed
change [sides v] by (-1)
broadcast [redraw v]

when [l v] key pressed
change [length v] by (10)
broadcast [redraw v]

when [k v] key pressed
change [length v] by (-10)
broadcast [redraw v]

// Drawing
when I receive [redraw v]
clear
go to x: (0) y: (0)
set pen size to (2)
set [angle v] to (360 / (sides))
pen down
repeat (sides) {
  move (length)
  turn (angle)
}
pen up

Conditional Loops Demo — repeat until

by Jungwon Kim • UCSD • Teaching Portfolio

Video (≤ 3 minutes)

Tip: In YouTube Studio → Subtitles, upload the provided conditional_loops_explainer.srt file as captions.

Program Purpose

The purpose of my program is to demonstrate Snap’s conditional loop repeat until. The cat sprite moves toward a yellow star and stops as soon as it touches the target color.

Blocks Used

when green flag clicked point towards [mouse-pointer v] repeat until <touching color [#FFFF00]?> move (5) steps say [I found the star!] for (2) secs

Why Conditional?

We don’t know in advance how many steps are needed. The distance to the star varies each run, so a fixed repeat (n) could stop too soon or go too far. A conditional loop runs until the condition becomes true.

How the Code Works

  1. Click the green flag to start.
  2. The sprite points toward the mouse pointer.
  3. repeat until <touching color [yellow]>: move 5 steps each iteration.
  4. As soon as the sprite touches the yellow star, the loop exits and the sprite says “I found the star!”.
Teacher Tips (optional for demo)
  • Turn on Snap’s Visible Stepper (footprints) so students can watch each loop iteration.
  • Move the mouse during a run to show the number of iterations changes.
  • Ask students to predict whether a fixed repeat would overshoot or undershoot.
